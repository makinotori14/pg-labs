# Лабораторная работа №1

## Проектирование и реализация реляционной базы данных

### Задание

По выданному варианту предметной области необходимо:

1. Выделить основные сущности, их атрибуты и связи.
2. Спроектировать реляционную модель данных, приведенную к 3НФ.
3. Построить ER-диаграмму с указанием:
   - таблиц и основных атрибутов;
   - первичных и внешних ключей;
   - связей.
4. Реализовать спроектированную БД в PostgreSQL.
5. Заполнить БД тестовыми данными.
6. Продемонстрировать работу ограничений целостности.

### Требования к базе данных

База данных должна содержать:

- не менее 5 содержательных таблиц;
- не менее 2 ограничений `UNIQUE`;
- не менее 3 ограничений `CHECK`;
- не менее одного составного ограничения;
- `NOT NULL` для обязательных атрибутов;

Необходимо использовать подходящие типы данных PostgreSQL. Выбор типов данных, ключей и правил `ON DELETE` должен соответствовать предметной области.

### Тестовые данные

База должна содержать достаточное количество данных для проверки всех связей и ограничений.

Необходимо подготовить минимум 5 некорректных операций `INSERT/UPDATE`, которые отклоняются PostgreSQL из-за созданных ограничений целостности.

### Изменение требований[^1]

После реализации исходной модели преподаватель выдаёт дополнительное изменение предметной области.

Необходимо изменить существующую структуру БД с использованием DDL (`ALTER TABLE`, добавление/изменение ограничений и т. п.).

Пересоздание базы данных не допускается. Существующие данные должны быть сохранены.

### Варианты предметной области

1. Интернет-магазин.
2. Система бронирования авиабилетов.
3. Информационная система университета.
4. Онлайн-кинотеатр.
5. Банковская система.
6. Служба доставки.
7. Медицинская информационная система.
8. Система бронирования гостиниц.
9. Сервис аренды автомобилей.
10. Система управления складом.
11. Система управления проектами.
12. Сервис продажи билетов на мероприятия.
13. Каршеринг.
14. Информационная система ресторана.
15. Система управления конференциями.

Конкретный состав сущностей, атрибутов и связей студент определяет самостоятельно исходя из предметной области.

Студент должен уметь объяснить назначение любого элемента представленного им SQL-кода.

Студент предоставляет:

- краткое описание предметной области;
- ER-диаграмму;
- описание основных проектных решений;
- обоснование приведения модели к 3НФ;
- `schema.sql` — создание структуры БД;
- `data.sql` — тестовые данные;
- `constraints_test.sql` — проверка ограничений;
- `migration.sql` — изменение структуры по дополнительному требованию.

**Срок выполнения до 20 октября**

[^1]: Это отдельная часть задания, которую можно будет сдавать отдельно, после прохождения этого материала
