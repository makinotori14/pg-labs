# Лабораторная работа №2. Система управления конференциями

```sh

```

Подключение: `localhost:5435`, база `lab02`, пользователь `postgres`,
пароль `postgres`.

## Задание 1.1. Подготовка данных

База взята из первой лабораторной. В миграции
[003_meeting_statuses.sql](migrations/003_meeting_statuses.sql) добавлены таблица
статусов `meeting_statuses` и поле `meetings.status_code`. Старые конференции
получают статус `planned`.

После миграций `001–003` выполняется [data/generate.sql](data/generate.sql).

- 130 записей в основных таблицах и 3 статуса. В `registrations` — 48 записей,
  в `events` — 24 события.
- 6 конференций завершены (`completed`), 2 запланированы (`planned`),
  1 отменена (`cancelled`).
- Данные за сентябрь, октябрь и ноябрь 2026 года.
- Одни и те же участники регистрируются на разные конференции.
- Есть 4 участника без регистраций, организатор без конференций, неиспользуемые
  комнаты и конференция без событий и участников.
- Для проверки крайних случаев есть конференция на одно место, оценки 1 и 10,
  полностью заполненная конференция и пустые поля (`NULL`).

## Задание 1.2. Операции изменения данных

Скрипт [data/dml.sql](data/dml.sql):

1. Создаёт конференцию, событие и регистрацию участника через `INSERT`.
   Её ID получаем через `RETURNING` и используем в следующих операциях.
2. Меняет статус конференции с `planned` на `cancelled` через `UPDATE`.
3. Увеличивает вместимость запланированных конференций ноября на 10 мест.
4. Удаляет созданную конференцию через `DELETE`. Связанные событие и регистрация
   удаляются автоматически благодаря `ON DELETE CASCADE`.
5. Отменяет все изменения через `ROLLBACK`.

Запуск после подготовки данных:

```sh
psql -d <имя_базы> -f lab02/data/dml.sql
```

## Задание 2.2. Агрегация и группировка

В [queries/aggregates.sql](queries/aggregates.sql) три запроса:

1. Количество регистраций на каждую конференцию через `COUNT`. Если регистраций
   нет, благодаря `LEFT JOIN` получается 0.
2. Конференции со средней оценкой выше 5. Среднее считается через `AVG`,
   условие задаётся в `HAVING`. Регистрации без отзывов не учитываются.
3. Количество конференций и общая вместимость по месяцам через `COUNT` и `SUM`.
   Отменённые конференции исключены, месяц определяется по московскому времени.

```sh
psql -d <имя_базы> -f lab02/queries/aggregates.sql
```

## Задание 3.2. Запрос с EXISTS

Второй запрос находит участников, у которых есть хотя бы одна регистрация
на запланированную конференцию. Наличие регистрации проверяется через `EXISTS`.
Каждый участник выводится один раз.

## Задание 3.3. Участники без отзывов

Третий запрос находит участников, зарегистрированных на завершённые конференции,
но не оставивших ни одного отзыва о них. `EXISTS` проверяет наличие регистрации,
а `NOT EXISTS` — отсутствие отзывов. Этим участникам можно напомнить об отзыве.

## Задание 3.4. Коррелированный подзапрос

Четвёртый запрос считает регистрации каждого участника. Подзапрос с `COUNT(*)`
считает только строки, где `r.member_id = u.id`, то есть регистрации текущего
участника. Если их нет, получается 0.

## Задание 4. Конференции, требующие внимания

В [queries/report.sql](queries/report.sql) сделан отчёт для организатора:
какие завершённые конференции получили низкие оценки или мало отзывов.

В отчёт попадают конференции, у которых:

- средняя оценка ниже 5 из 10;
- отзывы оставили меньше 50% зарегистрированных;
- нет отзывов или регистраций вообще.

Пороги 5 баллов и 50% выбраны для этого отчёта. Запланированные и отменённые
конференции не учитываются.

Схема вычислений:

Исходные данные → Промежуточные показатели → Агрегация → Итоговый отчёт.

Запрос разбит на четыре CTE:

1. `completed_meetings` берёт из `meetings` завершённые конференции и добавляет
   имя организатора из `creators`. Получается одна строка на конференцию.
2. `registration_details` добавляет к ним регистрации из `registrations`
   и оценки из `commentaries`. Получается одна строка на регистрацию.
   Благодаря `LEFT JOIN` конференции без регистраций тоже остаются в выборке.
3. `meeting_stats` группирует эти строки по конференции. Через `COUNT` считаются
   регистрации и отзывы, через `AVG` — средняя оценка. Снова получается одна
   строка на конференцию, уже с посчитанными значениями.
4. `meeting_metrics` считает долю отзывов от числа регистраций. Основной `SELECT`
   оставляет конференции по условиям выше и указывает причину. Если оценка низкая
   и отзывов мало, выводятся обе причины.

В результате видны конференция, дата начала, организатор, количество регистраций
и отзывов, доля отзывов, средняя оценка и причина попадания в отчёт.

Если отзывов нет, средняя оценка равна `NULL`. Если нет регистраций, доля отзывов
тоже равна `NULL`: от деления на ноль защищает `NULLIF`. Отзыв без текста,
но с оценкой учитывается. Доля считается от зарегистрированных, так как
посещаемость в базе не хранится. Числа округляются только при выводе;
ровно 5 баллов и ровно 50% сами по себе не считаются проблемой.

На данных из `generate.sql` отчёт содержит четыре конференции:

| Конференция | Регистрации | Отзывы | Доля отзывов | Средняя оценка | Причина |
|---|---:|---:|---:|---:|---|
| PostgreSQL: проектирование баз данных | 6 | 4 | 66,67% | 2,50 | Низкая оценка |
| PostgreSQL: индексы и оптимизация | 6 | 4 | 66,67% | 4,50 | Низкая оценка |
| Архитектура серверных приложений | 6 | 0 | 0% | `NULL` | Нет обратной связи |
| Визуализация данных | 6 | 0 | 0% | `NULL` | Нет обратной связи |

Запуск после подготовки данных:

```sh
psql -h localhost -p 5435 -U postgres -d lab02 -f lab02/queries/report.sql
```
