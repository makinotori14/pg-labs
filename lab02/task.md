# Лабораторная работа № 2

## Разработка SQL-запросов и аналитических сценариев для реляционной базы данных

### Общая постановка задачи

В лабораторной работе № 1 была разработана реляционная база данных для заданной предметной области. На данном этапе необходимо реализовать набор SQL-сценариев, обеспечивающих получение операционной информации и аналитических показателей из существующей базы данных.

Все задания выполняются на собственной модели данных из ЛР № 1.

Не допускается замена исходной предметной области, использование демонстрационных баз данных или создание отдельной упрощённой схемы специально для выполнения запросов.

Допускается расширение существующей модели дополнительными атрибутами и связями, если это необходимо для реализации аналитических сценариев. Такие изменения должны быть обоснованы и выполнены с сохранением ранее созданных данных.

### Часть 1. Подготовка данных и реализация операций DML

#### Задание 1.1. Формирование содержательного набора данных

Дополнить базу данных тестовыми записями таким образом, чтобы она содержала не только типовые, но и нетривиальные ситуации, характерные для выбранной предметной области.

Минимальные требования:

- Не менее 100 записей суммарно в содержательных таблицах, включая не менее 30 записей в одной из основных операционных таблиц.
- Не менее трёх различных состояний основного бизнес-процесса (например, создан, выполнен, отменён).
- Данные минимум за три различных календарных месяца, если предметная область предполагает учёт событий во времени.
- Наличие повторяющихся операций, связанных с одной сущностью.
- Наличие сущностей, для которых связанные операции отсутствуют.
- Наличие пограничных значений, в том числе нулевых показателей и `NULL` там, где это допускает модель.

Данные должны позволять получать содержательные результаты при группировке, фильтрации, соединении таблиц и аналитических вычислениях.

#### Задание 1.2. Операции изменения данных

Реализовать SQL-сценарий, включающий:

1. Добавление новой сущности и связанных с ней записей с помощью `INSERT`.
2. Изменение состояния существующей операции через `UPDATE`.
3. Массовое изменение нескольких записей по содержательному условию.
4. Удаление записи с помощью `DELETE` с учётом существующих ограничений целостности.
5. Демонстрацию отмены изменений с помощью `ROLLBACK`.

### Часть 2. Получение операционной информации

Разработать шесть SQL-запросов, решающих практические задачи выбранной информационной системы.

#### Задание 2.1. Многотабличные запросы

Реализовать три запроса с использованием `JOIN`, каждый из которых должен объединять данные не менее чем из трёх таблиц.

Запросы должны решать разные задачи:

- Получение подробной информации об операциях и связанных сущностях.
- Выявление объектов, у которых отсутствуют связанные записи.
- Получение перечня объектов, удовлетворяющих нескольким взаимосвязанным условиям.

Как минимум один запрос должен использовать `LEFT JOIN` и корректно обрабатывать отсутствие связанных данных.

#### Задание 2.2. Агрегация и группировка

Реализовать три аналитических запроса с использованием агрегатных функций и `GROUP BY`.

Необходимо предусмотреть:

1. Расчёт количественных показателей по группам.
2. Расчёт суммарных или средних показателей с фильтрацией групп через `HAVING`.
3. Сравнение показателей между категориями объектов или временными периодами.

В запросах должны использоваться не менее трёх агрегатных функций из `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.

Простое получение количества строк в таблице не считается самостоятельной аналитической задачей.

### Часть 3. Подзапросы и поиск нетривиальных ситуаций

Разработать четыре SQL-запроса, позволяющих выявлять объекты на основании информации о других объектах или совокупности операций.

#### Задание 3.1. Сравнение с вычисляемым показателем

Найти объекты, значение некоторого показателя которых превышает среднее значение по соответствующей группе. Группа сравнения должна определяться предметной областью.

Например, сравнение показателя конкретного объекта со средним показателем объектов той же категории.

#### Задание 3.2. Проверка существования связанных данных

Реализовать запрос с `EXISTS`, выявляющий объекты, для которых существует хотя бы одна связанная запись, удовлетворяющая дополнительному условию.

#### Задание 3.3. Поиск отсутствующих событий

Реализовать запрос с `NOT EXISTS`, выявляющий объекты, для которых отсутствует определённое событие или связанная запись.

Важно: отсутствие события должно иметь содержательный смысл в выбранной предметной области.

#### Задание 3.4. Коррелированный подзапрос

Реализовать запрос, в котором условие внутреннего запроса зависит от текущей строки внешнего запроса.

Запрос должен вычислять индивидуальный показатель или проверять индивидуальное условие для каждой рассматриваемой сущности.

### Часть 4. Комплексный аналитический отчёт с использованием CTE

Разработать один SQL-запрос, представляющий собой полноценный аналитический отчёт по выбранной предметной области.

Отчёт (в смысле некоторого осмысленного результата выполнения запроса, а не документа) должен отвечать на содержательный вопрос, который может возникнуть у руководителя, аналитика или оператора соответствующей информационной системы.

Студент должен представить схему вычислений:

Исходные данные → Промежуточные показатели → Агрегация → Итоговый отчёт

Для каждого этапа необходимо объяснить, какие данные поступают на вход, какие преобразования выполняются и какой результат формируется.
